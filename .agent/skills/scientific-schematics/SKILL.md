# Scientific Schematics

## Purpose

Create an accurate conceptual or structural diagram for a method, system,
mechanism, pathway, circuit, or study flow. The diagram and caption are the
product.

## Workflow

1. State the reader question and the exact components or stages.
2. Define each relationship and arrow meaning.
3. Remove items that do not help explain the method or mechanism.
4. Produce an editable diagram and one useful export.
5. Add concise labels and a caption that defines abbreviations and scope.
6. Open the result once and check scientific accuracy, readable labels, and
   unintended implications.
7. Apply venue dimensions only when they are known and required.

## Output Contract

Produce one editable schematic, one practical export, and a self-contained
caption. State any unresolved relationship briefly.

## Boundaries

- Do not begin with palette, font, dimensions, quality scores, or publication
  styling before the scientific structure is correct.
- Do not fabricate components, counts, causal arrows, or method details.
- Do not require a journal file, evidence record, prompt archive, or review log
  when the user has provided a clear diagram brief.
- Do not run repeated quality-review cycles without a concrete accuracy or
  readability problem.
- Use tools to create the actual diagram, not to generate scores or proof-of-work.
- Stop when the diagram is accurate and understandable; do not continue decorating.
